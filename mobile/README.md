# Hollow Chess mobile foundation

Capacitor 8.6.0 projects for iOS and Android reuse the website's game and the post-game feedback prompt. This is a development scaffold, not a signed or store-ready release.

## Build and open

Use Node 22 or newer. From `mobile/`:

```sh
npm ci
npm run sync
npm run open:ios
# or
npm run open:android
```

`build-web.cjs` copies only game assets into `www`, bundles the pinned Supabase and PeerJS SDKs locally, adds safe-area padding, and disables the website's service worker in the native runtime. It does not point a WebView at a remote site. Bot games and hotseat use local assets; accounts, matchmaking and submitting feedback require internet access.

The native projects are checked in; generated copies of web assets are ignored and regenerated by `npm run sync`. Never put signing credentials or private service keys into the app. The existing public Supabase key and insert-only feedback policy are used.

## Before external beta or store submission

- Confirm the application ID (`com.hollowchess.app`) and developer ownership, then configure Apple signing and Android release signing.
- Replace Capacitor's placeholder launcher icons and splash artwork with final Hollow Chess assets, including a proper 1024px iOS icon.
- Test real devices: touch input, safe areas, background/resume, offline bot play, keyboard, accessibility, matchmaking and feedback retry.
- Implement and test native auth callbacks before advertising account support: current OAuth, email confirmation and reset URLs are designed for the website. Configure Universal Links/App Links and Supabase redirect allowlists; retain guest play throughout. Password login may work but is not verified on native devices.
- Review sharing/copy-link and the Android back button on devices.
- Native analytics currently inherit the website's localhost exclusion. Add deliberate platform measurement and reflect it in the privacy disclosures before claiming native traffic metrics.
- Publish a privacy policy/support page, provide correct App Privacy and Google Play Data Safety answers, and finish account-deletion support if native accounts are offered.
- Use TestFlight / Google Play internal testing before public release. Store review and developer accounts are separate from generating these projects.

Android needs the SDK and current Capacitor-compatible Java toolchain; the machine's default Java 8 is insufficient. iOS requires a compatible Xcode and signing for physical devices or distribution. See the official [Capacitor setup](https://capacitorjs.com/docs/getting-started/environment-setup), [iOS release](https://capacitorjs.com/docs/ios/deploying-to-app-store), and [Android release](https://capacitorjs.com/docs/android/deploying-to-google-play) documentation.
